# 设计文档（当前态 + 决策记录）

> 本文记录"为什么长成现在这样"。原始顶层设计与完整变更日志见 [顶层设计-MCP化与桌面端.md](顶层设计-MCP化与桌面端.md)。

## 1. 定位与边界

**一句话**：只做多来源数据的收集与本地内容库，不接数据库、不接知识库、不做发布；所有能力通过三个入口暴露——Web 仪表盘（人）、MCP（Agent）、Electron 桌面壳（托付进程）。

明确不做：数据库/消息中间件、知识库接入（WeKnora 决策已移除）、内容发布、多用户。

## 2. 通道演进史（公众号）

| 阶段 | 通道 | 结局 |
|---|---|---|
| v0（fork 原始） | 微信读书中转（公共站/自建 we-mp-rss） | 上游接口官方下线（/web/login/platform* 404），2026-09 确认死亡 |
| v1 | mp_admin 管理员通道（Playwright 扫码 → searchbiz/appmsg） | searchbiz 可用；appmsg 撞 200013，实测证明是账号级频控 |
| v1.5 | 生态情报（2026-09-06 调研） | wechat-article-exporter（12k star）因上游接口关闭停维——判定 appmsg 族为不可靠依赖 |
| v2（当前） | **短链 `/s/{token}` 采集（主力）** + searchbiz 搜号 + 爆款洞察发现源 | 短链实测 15/15 成功；发现源免登录不受频控影响 |

**教训与决策**：
- 200013 不按"等待冷却"规划，按"上游收紧"规划 → 能力重心移到短链与发现
- 查询形态 URL（`s?__biz=…`）被微信环境校验拦截（连真浏览器都过不了），只有 `/s/{token}` 短链可靠 → 爆款条目采集失败属预期，前端给出短链重采指引
- PC 微信客户端凭证族（profile_ext + key 抓取）是生态仅存的批量历史通路，但依赖 PC 客户端 + 本机抓取，与 Docker 服务端架构冲突 → 桌面端候选特性，默认搁置

## 3. 关键设计决策

### 3.1 手写 MCP 而非 FastMCP
`typing-extensions==4.14.0`（mitmproxy 锁定）与 FastMCP 依赖冲突，权衡后手写 Streamable HTTP + JSON-RPC（协议 2025-03-26）。代价：协议演进需自行跟进（缓解：版本回显 + 明确错误提示 + stdio 兜底）。**已实现并验证，不再迁移。**

### 3.2 MCP 不对称暴露
46→50 工具中不含：删除历史、清理缓存、代理启停、证书安装。理由：agent 误操作半径控制；系统级变更保留给 Web 人工确认。

### 3.3 统一响应契约
所有 MCP 工具返回 `{success, summary, data, error{code,message,retryable}, request_id}`；资源类状态（任务、内容库、能力矩阵）同时暴露为 MCP Resources。借鉴 TrendRadar 的"配置驱动 + 统一响应 + output 即接口"思想，未照抄实现。

### 3.4 产物即接口
内容库 `output/` 是自包含契约（含 `_COMPLETE` 原子标记 + sha256 manifest + source_url 映射），知识库/下游系统直接读目录即可，无需调用 API——为将来接知识库预留的解耦点。

### 3.5 原子发布协议
条目先写 `.tmp` 目录，写 `_COMPLETE` 标记后 `os.replace` 原子改名。读取端（library、预览）只认含 `_COMPLETE` 的目录——杜绝读到半成品（跨文件系统场景不做原子假定）。

### 3.6 风控页守卫（2026-09-06 事故驱动）
爆款桥接曾把微信"环境异常"挑战页当成功文章入库。守卫规则：**先认文章标记**（`msg_title`/`activity-name`/`js_content`，防正文提及"环境异常"误伤），再查错误页特征（环境异常/参数错误/被删除/违规），兜底空壳页。命中 → 条目 failed + 短链重采指引。配套：去重索引按 value 清理避免挡住重采。

### 3.7 爆款洞察发现源（借鉴 creator-buddy）
第三方公开快照库（每日收录 10w+/低粉爆款/原创，覆盖近 30 天），关键词 → 四榜单，对数加权评分（分享权重最高，按公众号阅读量级缩放 1/3 防饱和），photoId 去重。**裁剪**：其 raw-socket 无 SNI + 关证书校验的请求方式（安全不可接受，实测标准 TLS 即可）；其写作建议类输出（超出"只负责收集"边界）。工具：`mp_hot_articles`；Web：采集页爆款卡片。

### 3.8 双运行时形态
Docker 为主（用户决策 2026-09-06），Native 为辅（开发与窗口扫码平台）。Electron `service-manager.js` 按 `runtimeMode` 切换：python 进程监督 或 `docker compose` 生命周期托管。

### 3.9 兼容修复记录（防回归）
- **base64 fakeid 过滤器**：官方 fakeid 以 `MjM5…==` 结尾 `=` 是正常的——`is_legacy_fakeid` 曾在 accounts.py 与 rss_scheduler.py 两处误杀（"收藏没变化""订阅重启被清"），已修：仅拒绝 `MP_WXS_` 前缀
- **预览渲染链**：CSP 白名单 + `data-src` 懒加载提升（正则 lookbehind 防 `data-src=` 子串误配）+ no-referrer + 本地图片重写（含 `&amp;` 形态）
- **Git Bash 环境坑**：`MSYS_NO_PATHCONV=1`、中文 JSON 走 python urllib、docker exec 路径转义

## 4. 已知限制

| 限制 | 影响 | 缓解 |
|---|---|---|
| appmsg 批量历史不可用 | RSS 增量调度受限、文章列表页受限 | 短链采集 + 爆款发现覆盖主要场景；RSS 订阅标记实验性 |
| Docker 下快手/小红书认证 | 窗口扫码无法出码 | 需 Native 模式完成认证，凭证共享 data/ 后回 Docker |
| 视频号依赖代理环境 | Docker 内需系统代理配置 | 仅 Web/桌面端配置，MCP 不暴露 |
| 第三方爆款库可用性 | 接口波动、脏链接 | 失败透明化（守卫 + 前端提示），无强依赖 |

## 5. P2 内容库设计落地

### 5.1 查询契约

`GET /api/library/entries` 支持 `platform`、`date`、`q`、`page`、`page_size`。不带 `q/page` 时仍返回旧版 `{entries: [...]}`；带任一查询/分页参数时返回 `{entries,total,page,page_size,has_more}`。正文全文索引暂不引入，先扫描元数据，规模性能由后续基准决定。

### 5.2 完整性状态

`GET /api/library/entries/{id}` 在原始 metadata 上增加 `integrity`：逐文件读取 manifest 中的 path/size/sha256，状态为 `complete`（全通过）、`partial`（原采集本身有失败或文件缺失）、`corrupt`（大小/hash 被篡改）。检查只读，不自动修复、不删除。

### 5.3 离线包

`POST /api/library/entries/batch-download` 接收 1-50 个 entry_id，输出 ZIP；仅从已提交 output 条目读取，限制 1000 文件/512MB。Markdown 中 manifest 映射到 `media/` 的远程图片 URL 会改写为包内相对路径；未保存资源保持远程链接并由完整性详情提示。此端点与 MCP 刻意保持 Web-only，避免 Agent 直接触发浏览器下载。

### 5.4 内容库备份

`backend/backup.py` 仅允许 output 白名单进入备份；ZIP 根部 `BACKUP_MANIFEST.json` 记录版本、文件数、总大小、逐文件 sha256。恢复先完整校验，再解压临时目录；默认 merge，replace 需显式传入且仍要求 Web `confirm=true`；完成后从 output 重建 dedup_index，不信任备份内索引。凭证和服务令牌永不恢复。

## 6. P3 可观测性与 Agent 体验落地

新增 `backend/core/environment.py` 作为无副作用的启动环境检查层，不主动请求任何外部平台；`GET /api/environment` 与 MCP `environment_check` 共享同一检查契约。状态分为 `ready`、`degraded`（可选依赖如 FFmpeg 不可用）和 `blocked`（端口/目录/磁盘等阻塞）。每项包含 `ok`、`message`、`retryable`，阻塞时 MCP 通过 `ENV_NOT_READY` 和 `blocking_checks` 告诉 Agent 下一步。

HTTP/stdio 两个 MCP 传输实现统一在 initialize 阶段处理客户端 `protocolVersion`：正常版本返回能力；版本不匹配仍完成握手但回显明确升级指引，避免静默兼容。工具总数由 49 增至 50。


## 7. 采集韧性设计

### 7.1 失败媒体补采
采集时的瞬时失败（防盗链、超时）不应永久损失媒体。`media_retry.retry_entry_media` 只处理 failed_items 中以 http 开头的条目，复用现有 `download_resource`，成功文件按 manifest 同款（path/mime/size/sha256/source_url）追加并原子写 metadata；失败文件不落盘（半截文件即删）。补采是修复不是重采：entry_id 不变、去重索引不动。

### 7.2 磁盘预算
采集半程磁盘写满会产出半成品内容。任务在 RUNNING 一开始检查 output 盘可用空间，不足立即结构化失败（retryable=true），跳过 runner。检查失败（OSError）时放行——预算是保护不是阻塞。

### 7.3 平台健康
健康数据只来自真实任务终态（不主动探测平台，避免触发风控）。分平台滑动窗口 200 条；错误按 user_input/auth/platform/internal 分类，让"平台故障"与"用户输错链接"可区分。样本 <10 标注 insufficient，UI 与 Agent 都不应据此宣称平台异常——这与爆款洞察的"诚实数据"原则一致。
